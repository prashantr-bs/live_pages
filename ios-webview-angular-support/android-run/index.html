Android run: AppA11y Rule Lab (Angular + Ionic in Android System WebView)

On-device scan of every rule page · Xiaomi 22021211RI, Android 14, WebView 152.0.7977.64 · BS talkback 1.1.39 (versionCode 44) as the accessibility service · on-device rule engine 2.0.5 · same APK as the iOS run (Angular 22.2 + Ionic 9.0.5 + Capacitor 8.5.2) · reported framework: native

70scans (every scroll position of 41 rule pages)
4,075web nodes captured (3,112 carry a name / text)
3,884of them isImportantForAccessibility=false
6 / 127expected-FAIL test cases reported FAIL (11 more flagged review / AI)
0FAILs on expected-PASS test cases
Unlike iOS, Android captures the web content. Chromium exposes the DOM as virtual AccessibilityNodeInfo nodes (Button, TextView, EditText, CheckBox, Switch… with names, headings, input types and URLs), and talkback serializes them. The rule engine then discards most of them: Chromium never marks virtual nodes importantForAccessibility, and 25 of 41 rules gate on that flag (isAccessible / shouldFocusView / speakableTextApplicable). Rules without the gate (touch-target, two-dimensional-scroll, the heading AI candidates, contrast) do reach web nodes, but contrast is capped at PASS / needs-review and truncation can never FAIL for web text (no font-size unit from Chromium). AI rules produce ai_review candidates whose verdict needs TCG, which was not run locally.

Method

  1. Installed A11yAngularPOC-1.0.0.apk. Enabled com.android.talkback/…TalkBackService (BSTalkback) via settings put secure enabled_accessibility_services, restored afterwards.
  2. adb forward tcp:9333 localabstract:webview_devtools_remote_<pid> (the app sets webContentsDebuggingEnabled). A CDP client navigates to /rule/<id> and scrolls ion-content in 85% steps. At each step it records the test-case stage rectangles in screen pixels (CSS px × devicePixelRatio + WebView top offset).
  3. Scan: am broadcast -a triggerAccessibilityScan --es sessionId local --es reportId r<ts> --es bsUserId dev --ez on_device_rules true. Wait for the TalkBackService: Accessibility scan completed log line, then run-as com.android.talkback cat …/accessibility_data/window.json → snapshot (screenshot stripped) + screenshot.png.
  4. Scoring: every rule-result element is attributed to the test case whose stage contains the element's centre. A FAIL test case counts as detected only if that rule emitted fail on an element inside it (needs_review / ai_review are shown separately).
