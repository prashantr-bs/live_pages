What this means for the roadmap

iOS: a capture problem. No rule can be fixed on its own: until web content becomes nodes, every rule stays blind. Order: (1) mark visible WKWebView regions as "web content not assessed"; (2) prototype the DOM extractor host-side through LCA's webviewInspect + ios_webkit_debug_proxy; (3) move it in-process (WKContentWorld) and add a web branch per rule. Design §8.
Android: a rule-engine problem. The DOM already arrives. Order: (1) accept isInScreenReaderTree as "accessible" for Chromium virtual nodes, which re-enables 27 rules; (2) OCR-derived text size for readable-text-size / spacing / magnification; (3) let OCR-verified contrast FAIL under the WebView root; (4) detect Capacitor / Ionic. Android analysis §A.
