Complete rerun of the real Angular apps on the current build

All four apps re-scanned on an iPhone (iOS 26) with the PR #360 injector at 5edda4d. Italo, Amtrak and DartCounter were driven by a script over Web Inspector (each screen reached by clicking through the app, scanned on device, closed again); T-mobilitat's native screens were tapped by hand while a scanner saved each new screen. Results are exactly what the injector reported; nothing is replayed or simulated. Counts are rule results on web elements (one element can fail several rules and repeat across screens); Accessible Interactive Elements is excluded (disabled in rule_config).

Verdict

  • Three WebView false-positive classes fixed in this round, each verified on device: toolbar backgrounds, gradient backgrounds, and web content behind a native sheet or alert (details below). None of them cost measurable scan time.
  • Web content now follows native rules wherever native has one: a gradient behind text makes the contrast rules abstain, a photo does not (both as native); a page behind a native sheet or alert gets the same behind-modal and covered flags as the native views beside it.
  • One known WebView gap remains (65 results): Italo's app page hidden under Apple's in-app Safari view. Text inside a disabled button (1 result in this run) and decorative-marked images of text were fixed afterwards (b430454, 24fb3d2).
  • Real issues are found across all three web apps: names that don't match the visible text, unnamed icon buttons, clickable divs with no role, placeholder-only fields, low contrast, small targets, truncated titles.
  • Extraction is solid: every web screen returned elements, no errors, no timeouts, median 28 ms.

Fixed in this round

Fixed Toolbar and action-sheet backgrounds 3ef51ec, 89797cb

Ionic paints ion-toolbar's colour on a shadow-DOM layer with pointer-events: none, which the sampler's elementsFromPoint skipped; the action sheet's dimmed backdrop was read as solid black. Italo's white titles now pass at 7.66:1 (were 1.16:1 against the page grey); Amtrak's action-sheet items are judged against the sheet.

Fixed Gradient backgrounds abstain, as on native 655bc57

Native abstains from contrast when its background walk crosses a gradient (CAGradientLayer) and walks past photos (UIImageView) to the next solid colour. The web sampler now does the same: a CSS gradient between the text and its ground makes the colour unknown and the rule abstains; near-transparent gradients (Ionic's 1px separators) and photos are treated as before. Contrast failures from gradients went from 32 (8 Amtrak promo-card titles over a photo with a dark scrim, 24 DartCounter gradient cards and buttons) to 1. The real low-contrast results on the same screens are unchanged.

Fixed Web content behind a native sheet or alert 0125ee2, 5edda4d

Italo shows a native cookie-consent sheet over its web page; Amtrak's "Passengers with a Disability" item raises a native alert. Native views behind them are flagged isBehindModal (the contrast rules skip them) and, where the sheet is opaque over them, isObscured; the web elements got neither, so they were judged as if nothing covered them. Each web element now gets the same flags from the same native walk (once per web view). On Italo's home with the sheet up, all 36 web elements are behind-modal and the 20 under the opaque sheet are obscured; its 4 contrast failures and 5 label results on hidden elements are gone. With Amtrak's native alert up, all 41 web elements are behind-modal. Swift-side scan time stays at 3–6 ms per screen before and after.

Highlighted rows in "Every scan" are screens where the web view was behind a native overlay (3 screens). Rules still evaluate behind-modal content the way they do for native views (contrast skipped, other rules applied).

Fixed Text inside a disabled button b430454, after this run

Italo's "Purchase a travel pack" form shows a disabled SEARCH button (faded red). WCAG exempts text in inactive controls, and the native rule skips text whose button, or a button up to 4 parents up, is disabled. Web elements are emitted flat under the web view, so that walk finds no button and the text is judged; and because a disabled Ionic button is pointer-events: none, its faded fill was also missed (1.11:1 against the page).

Fixed in b430454: text inside a disabled control is now nested under that control's node, as a UIButtonLabel is under its UIButton, so the native exemption applies; all other web nodes stay flat. Re-scanned on this screen only: the SEARCH contrast failure is gone and no other result changed; DOM time 19 → 22 ms (within run-to-run noise).

Fixed Images with text marked decorative (T-mobilitat) 24fb3d2, after this run

T-mobilitat's "Plan journey" intro is a Cordova web view inside the native SwiftUI app. Each slide is one image with alt="", text included, so screen readers skip it and no enabled rule reports it: images with an empty alt are treated as decorative and never reach Images with Text. The extraction is correct (4–5 web elements per slide); the gap was in rule coverage.

Fixed in 24fb3d2: Ruby's Images with Text is class-only (any image goes to AI, named or not); the on-device port also required the image to be an accessibility element. Web images now skip that gate, keeping the visibility, hidden-under-content and same-frame checks. Re-scanned on Plan journey slide 1 only: the slide image, the peeking edge of the next slide and the close icon now go to AI (none did before). Native images keep the gate.

WebView gaps after this run

FP · WebView Page hidden under Apple's in-app Safari view

Italo's "Italo in Real Time" opens the website italoinviaggio.italotreno.com in Apple's in-app Safari view (SFSafariViewController: close and address bar at the top, back / share / "open in Safari" at the bottom). This is not a new window inside the app's web view: it is a system browser screen presented over the app, and its page runs in Safari's own process, so the app (and the injector inside it) cannot read it or draw it. The scan therefore captures the app's own web page that is hidden underneath: in this run, 36 web elements and 65 results on a page the user can't see, with a blank screenshot. Re-checked on device: with the Safari view open, the scan is a duplicate of the home page behind it.

Fix: detect that a system browser view (or any presented screen the app can't capture) covers the app, and mark the page underneath as covered, as for a native sheet, or skip the scan. The website itself is out of scope for an app scan.

True positives

TP Accessible name doesn't match the visible text

Amtrak's booking fields show "Select Departure Station" but are named "Departure station, Double-tap to search stations"; "Add Coupon/Discount Code" is named "…dialog popup button, double tap to activate". Label in Name, Label at Front and View Type in Label report them.

TP Clickable elements with no role

DartCounter's game list rows and dashboard cards are clickable divs and custom elements with no role, so VoiceOver doesn't announce them as buttons and a keyboard can't reach them.

TP Placeholder-only fields

With the consent sheet gone, most Italo screens were scanned clean for the first time. Its "Search ticket" form names First Name / Last Name / Ticket Code only by their placeholders; there is no visible label.

Not covered

  • T-mobilitat: home, the three Plan journey slides, FAQs (content not loaded at scan time, as in round 1), Mobile and Card. Personal area and sign-in were skipped (login).
  • Amtrak: guest mode. "Purchase USA Rail Pass" and "Schedules" open external pages; Sign In / Join Now did not open from a scripted click; the travelers picker gave nothing new. The forced "Upgrade required" alert was closed once with Ionic's dismiss() before the run (hiding it instead leaves the page aria-hidden, which invalidated an earlier attempt).
  • DartCounter: guest mode (terms accepted by hand). The forced "Update available" dialog cannot be closed, so it was hidden; the page underneath was checked to be free of aria-hidden and inert before every scan.
  • Websites opened in Apple's in-app Safari view (Italo "Real Time") are outside the app and not scanned.
  • Italo: the consent sheet was up on the first two screens only in this run, so those show the behind-modal handling and the rest are clean.
  • Not verified: 8 ion-icon results for unnamed images. Ionic normally hides unnamed icons from VoiceOver, so these may be false positives; needs a DOM check.

How it was run

  • Injector: PR #360 at 5edda4d (Italo screens 03–18 and Amtrak 01–14 on 0125ee2, which differs only in a cache reset that matters when a native overlay appears between scans; the scans it affected were redone). Built locally (Xcode 26.6, Release, iphoneos) with the usual local-only test tweaks. Apps sideloaded with a free Apple ID.
  • Driving: pymobiledevice3 webinspector cdp; a script clicks each target by its visible text, waits, checks that nothing on screen is left aria-hidden by a stray overlay, scans, then returns and closes any overlay it opened. Each app was relaunched before its run so every screen counts once.
  • Before / after numbers come from the same crawl on 89797cb, and each fix was also checked by running the old and new extractor side by side on the live screens.
