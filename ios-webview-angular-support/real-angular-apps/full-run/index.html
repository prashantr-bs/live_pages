Complete rerun of the real Angular apps on the current build

All screens re-scanned on an iPhone (iOS 26) with the PR #360 injector at 89797cb, which includes the toolbar-background fix. Navigation was scripted over Web Inspector: each screen was reached by clicking through the app, scanned on device, and closed again. Results are exactly what the injector reported; nothing is replayed or simulated. Counts are rule results on web elements (one element can fail several rules, and repeat across screens); Accessible Interactive Elements is excluded (disabled in rule_config).

Verdict

  • The toolbar and action-sheet false positive is gone on every screen where it appeared (fix below). No WebView problem from earlier rounds came back.
  • Extraction is solid: every web screen returned elements, no errors, no timeouts, median 25 ms.
  • Two WebView gaps found, both open. The bigger one: Italo shows a native cookie-consent sheet on every screen, and the web page behind it is still checked, because web elements don't inherit the web view's behind-modal state. That makes all 565 Italo results in this run ones a native screen would skip; one Amtrak screen under a native alert adds 57 more. The other: contrast on photo / gradient backgrounds (32 results).
  • Web overlays are handled correctly: with an Ionic sheet or modal open, the page behind it is aria-hidden, reported as not accessible, and not failed by the label or keyboard rules.
  • Real issues are still found on Amtrak and DartCounter: names that don't match the visible text, unnamed icon buttons, clickable divs with no role, low contrast, placeholder-only fields, small targets.

Fixed since the manual scans

Fixed Toolbar and action-sheet backgrounds (3ef51ec, 89797cb). Italo's white titles on the red toolbar now pass at 7.66:1; in the manual scans they failed at 1.16:1 against the page grey. Amtrak's action-sheet items are judged against the sheet (#F9F9F9), not black. Old vs new extractor on 8 Italo screens and 5 Amtrak screens: only the header elements changed; extractor time unchanged.

WebView gaps found in this run

FP · WebView Web page behind a native sheet is still checked

Italo presents a native Didomi consent sheet over its web view on every launch, covering the lower half and dimming the rest. The native capture marks the WKWebView and every native view behind the sheet as isBehindModal and not accessible, so the rules skip them. The web elements inside that web view get neither flag: all 565 Italo results come from content the user can't reach. Amtrak's native "passengers with a disability" alert does the same to the page behind it (scan 09).

Fix: when mapping web nodes, OR in the host web view's isBehindModal and clear isWDAccessible the same way. Small change in the node mapping.

FP · WebView Contrast on photos and gradients

The background sampler reads CSS background colours. Amtrak's promo cards put white titles on a photo (an <img>), so the title is judged against the card's near-white fill. DartCounter draws its cards and buttons with CSS gradients and images, so their text and boundaries are judged against the page or against the control's own gradient.

Fix: when a photo or gradient sits between the text and the first solid background, don't guess: report the colour as unknown so the rule skips it (or sample screenshot pixels for those cases).

FP · WebView Same gap with a native alert

Amtrak's "Passengers with a Disability" item shows a native iOS alert over the web page. The web elements behind it were still judged; native views behind it were skipped.

True positives

TP Accessible name doesn't match the visible text

Amtrak's booking fields show "Select Departure Station" but are named "Departure station, Double-tap to search stations"; "Add Coupon/Discount Code" is named "…dialog popup button, double tap to activate". Label in Name, Label at Front and View Type in Label report them.

TP Clickable elements with no role

DartCounter's game list rows and dashboard cards are clickable divs and custom elements with no role, so VoiceOver doesn't announce them as buttons and a keyboard can't reach them.

Not covered in this run

  • T-mobilitat: only the native launch screen. Its web views sit behind native SwiftUI onboarding that has to be tapped by hand; the manual scans cover them.
  • Amtrak: guest mode. "Purchase USA Rail Pass" and "Schedules" open external pages; Sign In / Join Now did not open from a scripted click; the travelers picker gave nothing new. The forced "Upgrade required" alert was closed once with Ionic's dismiss() before the run: an earlier attempt that only hid it left the page aria-hidden and was discarded. A native alert left open by one screen was closed by hand and the following screens rescanned.
  • DartCounter: guest mode. The forced "Update available" dialog can't be closed, so it was hidden; the page underneath was checked to be free of aria-hidden and inert before scanning, unlike the earlier manual run. Upgrade, notifications and the bottom bar didn't open new screens for a guest.
  • Italo: "Italo in Real Time" opens an in-app browser in its own window; the scan still captures the home page underneath (known gap from the first round).
  • Not verified: 1 ion-icon results for unnamed images (Italo, Amtrak). Ionic normally hides unnamed icons from VoiceOver, so these may be false positives; needs a DOM check on device.

How it was run

  • Injector: PR #360 at 89797cb, built locally (Xcode 26.6, Release, iphoneos) with the usual local-only test tweaks (DOM layer and web-view inspection on under the sideload patch type). Apps sideloaded with a free Apple ID.
  • Driving: pymobiledevice3 webinspector cdp; a script clicks each target by its visible text, waits, scans, then returns by back button / router and closes any overlay it opened. The app was relaunched before each app's run so every screen counts once.
  • DartCounter's terms were accepted on the phone by hand.
