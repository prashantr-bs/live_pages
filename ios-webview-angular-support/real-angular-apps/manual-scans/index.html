Manual scans of four real Angular apps: how the WebView DOM layer holds up

You navigated each app on the iPad and scanned every screen you chose with manual-scan.sh; this covers screens the automated run could not reach (DartCounter's game modes, online lobby, tournaments, stats, account and profile; Italo's login dialog, search, loyalty, partners and offers; T-mobilitat's native sections; Amtrak's booking, trips, menu and train status). Injector: PR #360 head + the shadow-root loop fix, with the local-only test tweaks. The earlier automated analysis is unchanged.

Verdict

  • Extraction is solid. Every web screen returned elements (6–79 each), with no JavaScript errors and no timeouts after the shadow-root fix. Native screens (T-mobilitat's onboarding, home, card and account areas) correctly report no web view.
  • Most real issues are found: aria-labels that don't match the visible text (Amtrak), icon buttons without names (Italo, DartCounter), low contrast, placeholder-only fields, lower-case button names, clickable rows with no role.
  • Precision is the gap, not recall. Five false-positive patterns repeat across apps. Four are POC fixes in the extractor; the fifth (asterisk) is rule semantics. Fixing the three biggest (whole-page wrappers, Ionic hosts, overlays) removes most of the noise.
  • One test artifact: DartCounter scans 06–13 (highlighted below) ran with the update dialog hidden but still open, so Ionic kept the page aria-hidden and label / keyboard results on those screens are not representative. The extraction itself is correct for that state.

True positives

TP Accessible name doesn't match the visible text

Amtrak puts VoiceOver hints in its aria-labels: the field shows "Select Arrival Station" but its name is "Arrival station, Double-tap to search stations". A speech-input user saying the visible text won't hit it. Label in Name and Label at Front catch all of these.

TP Icon-only buttons with no name

Italo's header back / notification / profile buttons and DartCounter's round icon buttons have no accessible name; VoiceOver reads just "button".

TP Low contrast on correctly measured backgrounds

Examples: DartCounter's orange "Code of Conduct" link on the teal page (2.2:1), white input fields on the pale teal background (1.4:1 boundary), Amtrak's "One-Way" (4.1:1, below 4.5).

False positives

FP · new Toolbar title measured against the page

Italo's white page titles sit on a red ion-toolbar. The toolbar paints its colour from a CSS variable on a shadow-DOM layer that the background sampler misses, so the white text is judged against the page grey (1.1:1).

FP · seen before Whole-page wrappers, Ionic hosts, overlays

All three patterns from the automated analysis recur on screens it never reached, so they are systematic, not one-offs: whole-page click wrappers (59 results), Ionic host elements (65), and text behind overlays or covered elements (52). The required-field asterisk flagged as a special character (11) is rule semantics, the same on native.

What to fix, in order

  1. ✅ Skip page-level click wrappers — fixed (algorithm): a role-less tappable covering ≥60% of the web view or holding two or more controls becomes a non-interactive group.
  2. ✅ Treat Ionic hosts as the control — fixed (algorithm): button-like hosts (ion-button, ion-tab-button, ion-segment-button, ion-fab-button, ion-back-button, ion-menu-button, ion-chip, clickable ion-item) become buttons; layout / overlay hosts (ion-tab-bar, ion-modal, ion-alert, ion-action-sheet, ion-popover, ion-list, ion-header, ion-toolbar…) become groups.
  3. ✅ Overlays — fixed (algorithm): a web element the extractor already marks as covered is flagged behind-modal, so the contrast rules skip it exactly as they do native views behind a sheet. (Compositing backdrop alpha would need an extractor change; not needed once covered elements are skipped.)
  4. ⏳ Background sampling for shadow-DOM / CSS-variable colours (ion-toolbar) — extractor change, not done in this round.

Fixes applied: effect

All three are one pass over the extracted web nodes in Swift (bsMapWebNodes), using only the tag, rect and covered flag the extractor already captures: no extractor change, no extra DOM access, well under 1 ms. PR #360 1bc0a07 (plus the shadow-root fix f692b9a).
