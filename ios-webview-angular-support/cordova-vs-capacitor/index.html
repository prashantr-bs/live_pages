Angular + Cordova vs Angular + Capacitor on iOS

The same Angular 22 + Ionic 9 Rule Lab (41 rule pages, 208 test cases, 127 expected FAIL) was packaged in two native shells: “A11y Angular POC Cordova” (cordova-ios 8.1.1) and the existing Capacitor 8 app. Both were patched with the DOM-layer injector and scanned page by page on the same iPad Air 11" (M2, iPadOS 26.5). The only differences are the shell and how the scan driver navigates between pages. The Angular source is unchanged.

Conclusion

  • The POC is shell-agnostic. Cordova and Capacitor both host the page in a plain WKWebView, so the DOM layer extracts the same 2,200 web nodes and every rule reaches the same verdict on all 208 test cases.
  • Nothing in the injector or the rules depends on the shell. The cordova framework value is only a label.
  • Out of scope for both: legacy Cordova on UIWebView (cordova-ios before 6, rejected by the App Store since 2020), iOS below 14, and content inside iframes from another site.
