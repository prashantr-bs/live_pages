2 · The deciding rule (same in all three — only the tree differs)

For a focusable / clickable element, TalkBack decides:

1.  children == 0  → ANNOUNCE  (a childless control, e.g. an icon button, must get focus even if unlabeled)
2.  else, does it or its silent children have anything to speak? → ANNOUNCE
3.  else → SKIP  (a silent container — its contents get focused individually instead)

The bug is not in this rule. It's that Approach 3 changes the answer to “children == 0?” by deleting children the real phone still has.

3 · Why exactly these apps?

My Fitness Pal renders with Jetpack Compose; Indian Oil with Flutter. Both draw their UI through a virtual-tree provider instead of native Android views — the purple region above. The OS importance filter only ever runs on native views; it hands provider regions over unfiltered, so their “not important” internals legitimately exist on the real phone. Approach 3 deletes by the importance tag alone, so inside Compose / Flutter / WebView regions it removes nodes the phone keeps — and any silent focusable container whose children were all deleted flips from “skip” to “announce”. Fully-native screens (banana_club, etc.) have no provider region, which is why they matched perfectly.

Verified from the captures: all 11 surviving not-important nodes in MFP's flag-OFF tree sit under a ComposeView; Indian Oil's 12 sit under its full-screen provider host.

5 · The fix now being implemented — teach the rebuild the phone's second rule

The rebuild previously knew only one rule: "not important → delete". The phone actually applies two rules, and the missing one is what caused the deviation. Every element carries a hidden marker saying whether it was created by a real Android view or manufactured by a provider (Compose / Flutter / WebView) — the exact marker the OS keys on. The fixed rebuild reads that marker and applies both rules:

1.  real view & not important  → delete, lift its children up (unchanged — the native filter)
2.  provider-made element — or the host view a provider draws into  → always keep, importance ignored (new — the provider passthrough, exactly what the OS does)

Scope: one class (ImportantOnlyHierarchy, ~60 lines).
